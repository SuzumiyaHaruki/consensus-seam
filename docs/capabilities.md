# 七项测试控制能力总览

本文档面向 ConsensusSeam 使用者，说明 v0.1 分析的七项能力、分类方式和每次实验的总结产物。提供给 Agent 的英文合同位于 `spec/capabilities.yaml`。

## 能力分类

- `SUPPORTED`：系统边界内所有已发现的相关路径已经提供该能力。
- `PATCHABLE`：至少一条当前缺失路径可以通过低侵入修改补充；其他不可补充路径仍需报告。
- `PARTIAL`：部分路径已有能力，但剩余缺口都不能在 v0.1 中安全补充。
- `INVASIVE`：实现需要改变核心语义或发明目标没有定义的行为。
- `UNKNOWN`：源码证据不足。
- `NOT_APPLICABLE`：相对于当前系统边界不适用。

人工只负责定义系统边界，不负责列出目标内部实现路径。Analyzer 应发现所有输入、输出或控制边界实质不同的公开路径；Transformer 应尽可能覆盖所有低侵入可实现路径。

## 1. 消息捕获

目标：测试代码能够取得协议产生的出站消息，并阻止已捕获消息继续自动进入原有后续路径。

基本接口信息包括：

- pending 消息的稳定 ID；
- 发送方、接收方和消息类型；
- 捕获顺序；
- 列出和清空 pending 消息的入口。

不同路径可能在协议核心、应用传输层或测试环境中暴露消息，Agent 不能假定所有目标都有 `Transport`。

## 2. 消息注入

目标：测试代码选择一条已捕获消息，通过真实目标的正常协议输入入口进行投递。

成功注入只消费选中的消息，并保持发送方、接收方和内容。Agent 必须区分目标 ID 与目标对象绑定，说明节点对象或路由由谁持有。

## 3. 时间控制

目标：测试代码能够确定性推进协议观察到的时间。

v0.1 接受显式 Tick 或可注入 Clock，不增加直接制造选举或超时结果的捷径。

## 4. 随机性控制

目标：协议相关随机性可以固定或注入，使相同初始状态和种子产生可重复选择。

接口应保留目标原有随机算法和默认生产行为。

## 5. 生命周期控制

目标：把目标已有的停止、创建、恢复和状态所有权语义暴露给测试。

Agent 必须确认停止边界、恢复入口、状态所有权以及持久/易失语义。目标没有定义这些语义时，不允许 Agent 自行发明。

## 6. 状态观察

目标：暴露后续测试所需的最小节点或全局状态。

字段可以保持协议和实现特有，例如角色、任期、提交位置、应用位置或日志范围；v0.1 不设计统一状态 Schema。

## 7. 外部输入

目标：发现系统已有的应用工作入口，例如 proposal、read request、transaction 或成员变更。

它只做发现，不创建新的业务 API。点对点协议消息、Tick、定时器和内部回调不属于外部输入。

## 多路径记录

每项能力报告可以包含：

- `execution_paths`：Analyzer 发现的实质不同路径；
- `entrypoints`：目标已有入口；
- `covered_paths`：Agent 2 已实现或补充的路径；
- `uncovered_paths`：仍未覆盖的路径及原因；
- `limitations`：系统边界或 v0.1 范围限制。

未覆盖路径不是自动失败，但静默遗漏路径属于分析或实现问题。

## 每次实验的能力总结

每次运行生成：

- `capability-report.json`：机器可读的七项能力分析；
- `interface-report.json`：机器可读的新增接口说明；
- `USAGE.md`：面向使用者的中文总结，合并已有入口、新增入口、路径覆盖和限制。

analyze-only 运行没有 `interface-report.json`，但仍会生成 `USAGE.md`，总结目标已有能力和待补充能力。
