# 七项测试控制能力总览

ConsensusSeam v0.1 只面向 Go 共识实现。能力规范约束测试方最终能做的
事情，不规定统一类型、方法名、缓存结构或节点架构。提供给 Agent 的英文
合同位于 `spec/capabilities.yaml`。

## 分类与路径

- `SUPPORTED`：边界内所有已发现的相关路径已经完整提供该能力。
- `PATCHABLE`：至少一条缺失路径可以低侵入补齐。
- `PARTIAL`：部分路径可用，但其余缺口不能安全补齐。
- `INVASIVE`：需要改变核心语义或发明目标没有定义的行为。
- `UNKNOWN`：源码证据不足。
- `NOT_APPLICABLE`：相对于当前系统边界不适用。

人工只定义系统边界，Agent 从源码发现路径。一条路径表示测试方通过一组
一致的公开输出边界、缓存所有权、输入边界和控制方式驱动系统。不同公开
节点 API、输入输出边界、所有权或同步/异步控制面通常是不同路径；消息
类型、helper、文件和到达同一控制面的内部条件分支不是不同路径。同一运行
对象上的多个 accessor 只是入口，除非所有权、边界或完成语义发生变化。

消息捕获和注入必须使用同一组路径名称逐条分析。不能用 A 路径的捕获和
B 路径的注入拼成完整支持。每条未覆盖路径都要说明原因，但不能为了覆盖
而修改协议核心。

## 1. 消息捕获

目标：受控协议输出在投递前由测试可见缓存接管，后续投递只能由测试动作
触发。

测试方应能：

- 枚举缓存，查看目标原生消息内容和当前顺序；
- `Take` 一个实例并获得消息及已有路由信息；
- `Drop` 一个实例；
- `Clear` 缓存。

`Take` 属于捕获缓存操作：它移除并返回消息，但不负责协议投递。方法名并
不固定。一次性返回值、channel、投递后日志、不可控内部队列或测试方自行
创建的集合都只是原语，不是完整缓存。受控模式下捕获点必须拥有消息继续
传递权；另起消费者与协议消费者竞争读取不能构成可靠捕获。

测试方根据消息内容选择实例。实例引用可以是 record、handle、pointer、
token 或不会静默改变含义的 index。引用要么仍命中观察到的实例，要么明确
报告过期；不要求永久数字 ID。

## 2. 消息注入

目标：把捕获缓存中的具体实例通过同一路径的正常协议输入边界投递，保持
消息内容和目标不变。

允许两种形式：

### 分离式注入

```text
message := Take(reference)
ProtocolInput(target, message)
```

测试方已经持有真实目标对象关系时，可以根据返回的目标原生路由信息调用
正常输入。`Take` 后消息已离开缓存；后续重试、重新入队、重复投递或丢弃
由测试方决定。

### 组合式单调用注入

```text
Inject(reference)
```

facade 在一次调用中定位实例、绑定或校验目标、执行正常输入并更新缓存。
“单调用”不表示事务原子性。接口报告必须说明成功、同步失败和未确认异步
投递分别如何影响缓存。

如果目标采用请求—响应、response channel 或 future，捕获、移除、超时和
注入还必须保留并说明原有完成机制，不能让发送方或 future 静默失联。
捕获的请求必须进入正常请求处理入口；直接构造或完成响应不能代替请求
注入。只有缓存实例本身是响应时，才通过响应入口注入该实例。

两种形式都是完整注入，不要求同一系统同时提供两种。普通输入函数只有与
同一路径的捕获缓存建立明确关系后才算完整注入。

## 3. 时间控制

测试方能够通过显式 Tick 或可注入 Clock 确定性推进协议时间。已有接口可
直接使用时不重复包装；不得新增直接制造选举或超时结果的捷径。新增控制
值必须遵守目标合法范围。

## 4. 随机性控制

相同初始状态和控制参数能够重复协议相关随机选择。可以复用配置、固定值、
seed、注入随机源或测试构造器，但不能替换随机算法。接口要说明控制范围，
保持生产默认行为并校验合法值域。同一声明范围内，相同实例必须获得相同
随机选择；如果并发调用顺序会改变共享随机序列与实例的对应关系，仅设置
全局 seed 不能算完整支持。

## 5. 生命周期控制

测试方能够让指定逻辑节点停止协议活动，并在之后重新参与。实现可以是
pause/resume、stop/reconstruction、调用方停止/恢复调度或进程级控制。

已有操作可以直接组合时即满足能力，不要求为了对称性增加 convenience
wrapper。报告应说明同一实例恢复还是重新构造；除非目标已经定义，否则不
声称生产 crash、持久状态或易失状态语义。网络断连、丢包或分区时节点仍在
执行本地协议活动，因此不能单独证明生命周期不可用。

## 6. 状态观察

暴露测试所需的最小目标原生节点或全局状态。已有 Status 足够时直接复用，
状态分散时可以增加只读 accessor。返回结果不能通过共享可变数据修改内部
状态；Go 结构体按值复制后仍要检查嵌套 slice、map、pointer、interface 和
可消费流。v0.1 不设计统一状态 Schema 或正确性 oracle。

## 7. 外部输入

发现已有 proposal、read request、transaction、成员变更或其他应用工作
入口，并生成清晰清单。它只做发现，不创建业务 API。点对点协议 ingress、
Tick、定时器、内部 callback，以及诊断、barrier、snapshot/restore、
bootstrap、领导权转移、生命周期和维护操作不属于外部输入，除非目标明确
将其定义为应用工作负载。

## 通用实现与审查原则

- 区分底层原语和测试方可直接使用的完整接口；
- 复用已有能力，缺失时才包装、暴露或最小实现；
- 如实记录外部、同包测试和内部 harness 的调用范围；
- 返回快照不能泄漏可变别名；
- 成功、失败和控制状态变化必须与报告一致；
- 使用示例必须使用正确 receiver 和声明范围可见的真实符号；无法确认时应
  省略，不能使用省略号、伪造 helper 或未导出字段；
- Agent 2 只添加验证新增行为所需的最少测试，不扩写重复或穷举测试。

每次运行通过 `capability-report.json`、`interface-report.json`、`USAGE.md`
和 `AUDIT.md` 分别记录修改前事实、生成接口、使用方式和独立审查结论。
`patch` 已经能够产出候选；`repair` 只是生成后的可选质量增强流程。
